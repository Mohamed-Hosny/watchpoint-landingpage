# Watch Point — صفحة هبوط عربية (RTL)

صفحة هبوط ثابتة بالكامل لشركة **Watch Point** للأنظمة الأمنية وكاميرات المراقبة. مبنية بـ HTML5 وCSS3 وJavaScript فقط، بدون أي إطار عمل أو خادم خلفي، وتعمل محليًا دون اتصال بالإنترنت (ما عدا روابط واتساب التي يفتحها المستخدم بنفسه).

## المحتويات

- صفحة رئيسية كاملة: هيدر، هيرو، 7 أقسام رئيسية بفئات فرعية، 3 باقات، خدمات، نبذة، خطوات العمل، أسئلة شائعة، نموذج طلب عرض سعر.
- بحث وفلاتر للمنتجات مع تطبيع الحروف العربية.
- مؤشر تقدم عائم للصفحة يعرض موضع التصفح ويعيد إلى الأعلى عند الضغط.
- أزرار واتساب تحمل اسم المنتج/الباقة المختارة داخل الرسالة.
- نموذج تحقق كامل يحوّل الطلب إلى رسالة واتساب جاهزة (بدون ادعاء إرسال أو حفظ على الخادم).
- 7 صفحات SEO ثابتة للأقسام الرئيسية داخل `catalog/` + صفحة دليل الأقسام.
- بيانات منظمة JSON-LD، و`sitemap.xml`، و`robots.txt`، و`llms.txt`.
- Google Analytics 4 مع موافقة مسبقة (اختياري، معطّل افتراضيًا).
- طبقة بيانات جاهزة للربط المستقبلي بـ Django REST API أو ERP.
- خطوط وصور محلية بالكامل داخل `assets/`.

## التشغيل محليًا

يفضل تشغيل المشروع عبر خادم محلي بدل فتح `index.html` مباشرة:

```bash
cd watch-point-landing
python -m http.server 8123
```

ثم افتح:

```text
http://127.0.0.1:8123/
```

أي خادم ملفات ثابتة آخر يعمل أيضًا، مثل:

```bash
npx serve .
```

> ملاحظة: فتح الملف مباشرة عبر `file://` قد يمنع بعض المتصفحات من تحميل الخطوط أو تنفيذ طلبات الـ API مستقبلًا. استخدم خادمًا محليًا.

## لوحة التحكم — إدارة المنتجات والأسعار

يوجد داخل المشروع لوحة تحكم عربية كاملة تعمل محليًا بدون قاعدة بيانات وبدون أي حزم خارجية (Node.js فقط):

- إضافة وتعديل وحذف المنتجات، مع رفع الصور وتحديد السعر والتوفر والمنتج المميز.
- إدارة الباقات ومكوناتها وأسعارها.
- تعديل بيانات الفئات الأساسية وبيانات SEO لكل فئة (العنوان والوصف وH1 والمقدمة).
- تعديل رقم واتساب والهاتف والبريد والعنوان ورابط الموقع ومعرّف Google Analytics.
- زر **«نشر التغييرات»** يحدّث `js/data.js` و`js/config.js` ثم يعيد توليد صفحات `catalog/` و`sitemap.xml` و`privacy.html` تلقائيًا، بما في ذلك صفحة مستقلة لكل منتج `catalog/product-<slug>.html` وصورة الفئة داخل صفحتها.

### التشغيل

من جذر المشروع (المجلد الأب) اضغط دبل كليك على:

```text
start-admin.bat
```

أو من الطرفية:

```bash
cd watch-point-landing
node admin/server.mjs --port=8123
```

ثم افتح:

```text
http://127.0.0.1:8123/admin
```

- في أول تشغيل ستُطلب منك إنشاء كلمة مرور (8 أحرف على الأقل). تُحفظ مشفّرة بـ scrypt في `admin/data/auth.json`.
- بيانات الإدارة كلها في `admin/data/store.json` (انسخ مجلد `admin/data` للنسخ الاحتياطي).
- كل عملية نشر تُنشئ نسخة احتياطية من `js/data.js` و`js/config.js` داخل `admin/data/backups/` (آخر 10 نسخ).
- السيرفر يقدّم الموقع ولوحة التحكم معًا؛ لا تحتاج تشغيل خادمين.

> السيرفر يستمع افتراضيًا على `127.0.0.1` فقط. عند النشر على خادم خارجي استخدم HTTPS وكلمة مرور قوية، واضبط `HOST=0.0.0.0` عند الحاجة، ولا تفتح `/admin` للعامة دون حماية.

### ملاحظات الإدارة

- بعد أول تشغيل تصبح `admin/data/store.json` هي المصدر؛ تعديل `js/data.js` يدويًا لن يظهر في اللوحة. لحذف بيانات اللوحة وإعادة التهيئة من ملفات الموقع الحالية، احذف مجلد `admin/data` ثم أعد التشغيل.
- الصور المرفوعة تُحفظ في `assets/images/uploads/`.
- لتغيير كلمة المرور استخدم قسم «بيانات الموقع»، أو احذف `admin/data/auth.json` لإعادة إنشاء كلمة مرور جديدة.
- ملف `start-watchpoint.bat` في الجذر يبقى لتشغيل الموقع فقط عبر Python بدون لوحة التحكم.

│  ├─ server.mjs              سيرفر الموقع + لوحة التحكم
│  ├─ store.mjs               حفظ البيانات والنشر وتوليد الملفات
│  ├─ auth.mjs                كلمة المرور والجلسات
│  ├─ views.mjs               صفحات اللوحة العربية

│  └─ data/                   يُنشأ تلقائيًا: store.json وauth.json وbackups/

## أهم ما يجب تعديله قبل النشر

### 1) رقم واتساب وبيانات التواصل

افتح `js/config.js` وعدّل:

```js
contact: {
  // رقم دولي بدون + أو مسافات، مثال: "201012345678"
  whatsappNumber: "",
  phone: "",
  phoneDisplay: "",
  email: "",
  address: "",
  serviceArea: "مصر",
  workingHours: ""
}
```

- اترك أي قيمة فارغة إن لم تكن متاحة؛ الواجهة تعرض بديلًا آمنًا ولا تخترع بيانات.
- عند ترك `whatsappNumber` فارغًا: يفتح الموقع واتساب كرسالة مشاركة، وينسخ نص الطلب تلقائيًا، ويظهر تنبيه يوضح أن الرقم لم يُضبط بعد.
- `phoneDisplay` هو النص الظاهر، و`phone` هو الرقم الذي يُستخدم في رابط الاتصال.

### 2) رابط الموقع الحقيقي

```js
site: {
  url: "https://your-domain.com"
}
```

- عند تركه فارغًا تعمل الصفحات محليًا بروابط نسبية.
- قبل النشر اضبطه ثم أعد توليد ملفات SEO:

```bash
node tools/generate-seo.mjs
```

سيؤدي ذلك إلى تحديث `catalog/` و`privacy.html` و`sitemap.xml` و`robots.txt` و`llms.txt`، واستخدام النطاق الفعلي في الروابط المطلقة والبيانات المنظمة.

> في الوضع الحالي `site.url` فارغ، لذلك تستخدم خرائط الموقع النطاق المؤقت `https://watchpoint.example.com`. استبدله قبل النشر.

### 3) المنتجات والأسعار والباقات

كل البيانات في `js/data.js`:

- `WP_CATEGORIES`: الأقسام الرئيسية السبعة وفئاتها الفرعية ومحتوى SEO.
- `WP_PRODUCTS`: المنتجات. كل منتج له `id` فريد وثابت و`slug` و`categoryId`.
- `WP_PACKAGES`: الباقات الثلاث.

السعر `null` يعني عرض «اطلب آخر سعر». عند إدخال سعر حقيقي استخدم رقمًا:

```js
price: 1250,
priceCurrency: "EGP"
```

لا تضع أسعارًا أو موديلات أو مواصفات غير مؤكدة. النصوص الحالية تجريبية وموسومة بذلك بوضوح.

بعد أي تغيير في الفئات أو الـ slugs، أعد توليد صفحات SEO:

```bash
node tools/generate-seo.mjs
```

### 4) Google Analytics 4

```js
analytics: {
  measurementId: "G-XXXXXXXXXX",
  requireConsent: true,
  consentStorageKey: "wp_analytics_consent_v1",
  debug: false
}
```

- التحليلات معطّلة تمامًا عندما يكون `measurementId` فارغًا، ولا يُحمّل أي سكربت خارجي.
- عند إضافة المعرّف يظهر شريط الموافقة، ولا يُحمّل GA إلا بعد الضغط على «موافقة».
- الأحداث المتتبعة تشمل: `whatsapp_click`، `quote_request`، `search`، `filter_products`، `package_select`، `faq_open`، `analytics_ready`.
- لا تُرسل بيانات شخصية من النموذج إلى التحليلات.

## الربط المستقبلي بـ ERP / Django REST API

الواجهة لا تعتمد على بنية HTML للمنتجات؛ يمكن استبدال المصدر المحلي بـ API:

```js
data: {
  source: "api",
  catalogEndpoint: "https://erp.example.com/api/catalog/"
}
```

الشكل المتوقع للاستجابة (أو استجابة `results` من DRF مع تعديل بسيط في `normalizeCatalog`):

```json
{
  "categories": [
    { "id": 1, "name": "كاميرات داخلية", "slug": "indoor-cameras", "description": "..." }
  ],
  "products": [
    {
      "id": "SKU-001",
      "slug": "indoor-camera-x",
      "category_id": 1,
      "name": "كاميرا داخلية",
      "description": "...",
      "image": "https://erp.example.com/media/cam.jpg",
      "image_alt": "كاميرا داخلية",
      "specs": ["اتصال شبكي"],
      "price": 1250,
      "price_currency": "EGP",
      "availability": "quote"
    }
  ],
  "packages": []
}
```

- تحتفظ `WPData` بالبيانات المحلية كبديل تلقائي إذا فشل الاتصال.
- استخدم `id` فريدًا وثابتًا لكل منتج؛ لأنه يُستخدم في روابط طلب العرض ورسائل واتساب.
- راجع دالة `normalizeCatalog` في `js/data.js` إذا كان شكل استجابة الـ API مختلفًا.

## توليد صفحات SEO

```bash
node tools/generate-seo.mjs
```

المولّد يقرأ `js/config.js` و`js/data.js` ويكتب:

- `catalog/index.html`
- `catalog/<category-slug>.html` لكل فئة
- `catalog/product-<product-slug>.html` لكل منتج
- `catalog/catalog.json`
- `privacy.html`
- `sitemap.xml` و`robots.txt` و`llms.txt`

لا تعدّل الملفات المولدة يدويًا إن كنت ستشغّل المولّد مرة أخرى؛ عدّل القالب داخل `tools/generate-seo.mjs` أو البيانات في `js/data.js`.

## الـ SEO والـ AEO/GEO

- كل صفحة تحتوي عنوانًا ووصفًا وCanonical وOpen Graph وTwitter Card.
- الصفحة الرئيسية تحتوي JSON-LD لـ Organization وWebSite وWebPage وService وItemList وFAQPage.
- صفحات الفئات تحتوي BreadcrumbList وCollectionPage وFAQPage وبيانات المنتج.
- `robots.txt` يسمح لزواحف محركات البحث ومساعدات الذكاء الاصطناعي العامة.
- `llms.txt` يلخص حقائق الشركة والصفحات لمحركات الإجابة.

## ملاحظات مهمة

- لا يوجد خادم خلفي ولا قاعدة بيانات؛ إرسال الطلب يتم عبر واتساب فقط.
- لا تُحفظ بيانات النموذج على الموقع.
- جميع الصور والرسوم محلية، ولا تعتمد على CDN أو مكتبات خارجية.
- النصوص الحالية لا تدّعي تقييمات أو شهادات أو شراكات أو مدد ضمان غير مؤكدة.
- إذا أضفت رقم هاتف أو بريدًا أو عنوانًا، تأكد من صحته الرسمي أولًا.
